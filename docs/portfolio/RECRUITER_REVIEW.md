# Recruiter experience review

Heuristic desk review, 5 November 2026. These are reviewer judgments on repository
content, not observed recruiter behaviour, hiring outcomes or a user study. Scores are
0–5. The website section/profile text are local proposals and earn no live-deployment credit.

## Visitor A — HR recruiter, 30 seconds

Route: central README → overview → working Hub screenshot. Positioning: practical
enterprise AI work connecting business decisions, tested automation and responsible
experimentation. The first screen names the fictional case and AI support; inspectable
artifacts demonstrate work rather than unsupported seniority.

| Dimension | Score | Evidence / remaining friction |
|---|---|---|
| Clarity | 4 | README names problem, three stages and quick routes; still three repositories |
| Credibility | 5 | Synthetic case and AI assistance disclosed; negative value and failed gates visible |
| Technical evidence | 4 | Source/tests/CI links direct; HR may not inspect code |
| Business relevance | 4 | Request handoffs and pilot decision concrete; no measured customer result |
| Visual quality | 4 | Actual Hub captures, editable overview and executive cover; no finished short video |
| Navigability | 4 | Main links and short routes; website/profile additions await review |
| Interview usefulness | 4 | Clear tradeoffs to ask about; contribution ledger requires owner input |

## Visitor B — technical hiring manager, three minutes

Route: Hub `src/Program.cs`/tests → Agent frozen report → real HTTP integration workflow.
Look for API authority, persistence/error boundaries and why deterministic evidence is
separate from model accuracy. Nothing here proves independent production ownership.

| Dimension | Score | Evidence / remaining friction |
|---|---|---|
| Clarity | 4 | One API authority; optional model path and explicit confirmation separate |
| Credibility | 5 | Failed holdout/raw outputs preserved; no autonomous approval or tenant claims |
| Technical evidence | 4 | 16/27/17 tests, browser and real HTTP checks; no production load/recovery assurance |
| Business relevance | 4 | Requirements link to workflow/acceptance; remains a small local reference |
| Visual quality | 4 | Actual architecture and current report route; no standalone agent GUI |
| Navigability | 4 | Code map and direct failure report; historical reports require date awareness |
| Interview usefulness | 5 | Retry/concurrency/abstention exercises expose real understanding rather than rehearsed buzzwords |

## Visitor C — business/product leader, five minutes

Route: executive PDF → requirements/BPMN → base/scenarios → pilot go/no-go.
The value is disciplined decision-making: do not invest in a model rollout simply because
a prototype runs. All workshop, cost and adoption inputs are assumed.

| Dimension | Score | Evidence / remaining friction |
|---|---|---|
| Clarity | 4 | Named process/owners and decision; supporting detail is longer than a pitch |
| Credibility | 5 | Financial loss retained, capacity separated from cash, no invented clients |
| Technical evidence | 4 | Working slice and reproducible formulas support feasibility; no tenant acceptance |
| Business relevance | 4 | Cost/risk/adoption/go-no-go connected; real demand/baseline not measured |
| Visual quality | 4 | Ten-page executive PDF and process comparison; PDF not fully tagged |
| Navigability | 4 | Central business entry and timed route; no public live business application |
| Interview usefulness | 5 | Can discuss stopping/simplifying, stakeholder ownership and exception handling |

## Review conclusion

Strong enough for a portfolio conversation about business analysis, functional analysis,
automation prototypes and AI evaluation practice. It does not alone support senior
production AI/security/cloud expertise. Next improvement is owner rehearsal and a short
captioned demonstration, not more software. Observe an actual reviewer before treating
these heuristic scores as validated usability.
